# AKU9992 — Native12 x64 Fix4

8 октября 2026. Авторство сборки: AKU9992.

## Изменения

Standard по умолчанию задаёт min(60, активная частота экрана); Auto — частоту дисплея с игровым окном; Custom — выбранный предел до этой частоты. Частота хранится как отношение целых чисел без округления в таймере. Перенос окна проверяется каждый кадр, смена режима экрана — раз в секунду. Если частота недоступна, используется 60 Гц, числовая причина записывается в AKU9992-frame-control.log без идентификатора дисплея.

Настройки: AKU9992-Settings.cmd или generals.exe --settings. Client/AKU9992-settings.ini действует со следующего запуска. VSync выбирается отдельно, в фоне предел 30 FPS. Оборудование может давать FPS ниже цели. Diagnostic доступен только при явно включённом профилировании/тестировании. Ожидание кадра использует QPC и waitable timer без активного вращения. DXGI flip-discard имеет три буфера; allocator/uploads переиспользуются после fence. Tearing flags согласованы с Streamline перед Present. VRR и минимальная задержка ввода не подтверждены.

Симуляция при обычной скорости остаётся 30 Гц: учитывается всё прошедшее время, выполняются до 32 догоняющих тиков, остаток долга сохраняется. Сетевая готовность обновляется отдельно для каждого тика; недостающие команды не заменяются. ИИ и частицы обновляются на тиках симуляции. Ползунок скорости игры управляет симуляцией, а не FPS. Визуальный коэффициент учитывает elapsed time, логическое состояние не интерполируется отрисовкой.

Подтверждённое узкое место исходных сцен — подготовка рендера на CPU. Общие вершины индексированных triangle/line/point lists преобразуются один раз и выводятся через DrawIndexedInstanced. Для разреженных диапазонов и strip/fan сохранён прежний путь. Качество, вода, тени, текстуры, число объектов и правила ИИ ради FPS не снижались. Добавлены opt-in фазы CPU, асинхронные GPU timestamps и VRAM. pathfind_ms пока не инструментирован: ноль не означает отсутствие затрат поиска пути.

Сохранены исправления звука, иконок, полос интерфейса и прокрутки мышью.

## Фактическое состояние

Оба игровых EXE, launcher и backend — AMD64. Проверяются загруженные D3D12/DXGI и отсутствие D3D8/D3D9. Совместимые W3D/D3D8 имена остаются внутренним ABI; ресурсы, материалы, вода, отражения и stencil-тени исполняются через D3D12. Это замена backend существующего W3D, а не полностью новый движок. Неиспользуемые legacy-файлы исходной установки могут оставаться; проверка AMD64 относится к запускаемым EXE и загружаемым DLL.

Исходная база закреплена на commit b805c12ee1aedc0a4b241006803b8e04bbf288a6. DDS сохраняет 124-байтный дисковый заголовок; указатели и Windows messages исправлены под AMD64. Object pool проверен на выравнивание, связи блоков и повторное уничтожение. Загрузка текущего сохранения и реального повтора проверена. Исправлены создание папки Save перед извлечением карты и восстановление IP единственного локального слота без изменения формата файла. Очистка временных .map ограничена папкой Save и не меняет рабочую папку процесса. Полная совместимость произвольных старых x86 сохранений/повторов не доказана. Перенос x64 Bink-видео остаётся незавершённым.

Используется официальный Streamline 2.14.1 с проверкой подписи runtime. GPU-тесты подтверждают настоящие DLAA/DLSS Quality и выходные пиксели. Передаются color, depth, motion vectors и jitter; GUI выводится после обработки мира. История сбрасывается при смене сцены/размеров/viewport и скачке камеры. Предусмотрен Native fallback; неподдерживаемого адаптера для реального теста не было. Balanced/Performance и Frame Generation не заявляются. API сверены с [NVIDIA Streamline DLSS](https://github.com/NVIDIA-RTX/Streamline/blob/main/docs/ProgrammingGuideDLSS.md) и [Microsoft QueryDisplayConfig](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-querydisplayconfig).

## До и после

Оборудование: Intel Core i7-13800H, 14 ядер/20 потоков; NVIDIA RTX A1000 6GB Laptop GPU, драйвер 596.41. Активный экран: 26880000/447712 Гц. Идентификаторы компьютера и учётной записи не приводятся.

До изменений сохранены отдельные бинарные файлы Fix3 и SHA256. После игровых проверок отдельно повторены исходные и новые бинарные файлы; пустой параметр тестового сценария не запускает дополнительную схватку: одинаковые shell map сцены запускались последовательно по 20 секунд при одинаковых разрешениях/настройках High. Первые 5 секунд исключены. Это не полноценные сетевые бои. Diagnostic снимает лимит только для измерения. Ранний и повторный прогоны сохранены отдельно; основные таблицы используют последовательную пару после завершения сборок и GUI-проверок. Частоты CPU/GPU и температурный режим не фиксировались, поэтому разброс нельзя приписывать только изменению кода. По одному прогону в этой паре ограничивает уверенность, особенно 0,1% low.

Средний FPS = 1000 / средний frame time. 1%/0,1% low = обратная средняя длительность худшего 1%/0,1% кадров. CPU — суммарное CPU-время процесса на кадр. GPU — асинхронные timestamps command list без Present и внешней CPU-подготовки. GPU до изменений не записывался: в таблице только измеренный GPU после.

## Подтверждения и ограничения

- CRC, число объектов и координаты юнита сверяются на одинаковых тиках при 15 и Standard 60 FPS. verification.json содержит только фактически завершённые проверки текущих файлов.
- Диалог FPS собран. Функции загрузки/сохранения Standard, дробного Custom, VSync и fallback неверных значений проверены через действующую сборку launcher. Визуальная ручная проверка диалога не выполнялась.
- Таймер 59,94 FPS проверен 120 кадрами. Есть тесты целей 119,88, Custom, fallback, фона, диагностического допуска и сохранения elapsed при задержке 250 мс. Физического экрана 120/180 Гц не было.
- Регрессионные проверки подтверждают создание Save, защиту файлов за её пределами, сохранение .sav/вложенных .map и восстановление единственного локального слота без подмены нескольких игроков.
- GPU pixels проверяют 16/32-bit indices с ненулевыми base/minimum, текст, выключенные иконки, mip-текстуры, материалы, свет, воду, отражения и stencil-тени. Resize/recreate проверены при 640×480, 3440×1440, 3840×2160 и 641×479.
- Проверены pooled audio rates 11025/22050/44100/48000, pitch, PCM/ADPCM, MP3, pause/resume, EOS и освобождение ресурсов.
- D3D12 debug layer недоступен: создание устройства вернуло 0x887A002D. Его проверка не прошла; обычные hardware/GPU/resize тесты доступны.
- Нет второго участника для LAN/онлайн, монитора 120/180 Гц, неподдерживаемой GPU и полного набора старых x86 сохранений/повторов. VRR, ручные Alt+Tab/переезды между дисплеями и отсутствие ghosting DLSS на всех эффектах не подтверждены.
- Сетевой тест: одинаковый выпуск на двух участниках, разные лимиты 15/60/Auto, одна карта/seed, длительное движение/строительство/бой, сверка CRC и повторов. Смена частоты Windows: новая rational refresh в логе, пересчёт цели в течение секунды.
- В пятиминутной игре средние RAM/VRAM между интервалами 60–120 с и последней минутой составили 726,15 → 740,93 MiB и 174,73 → 176,95 MiB. Число объектов росло. Прогон проверяет короткий тренд памяти после прогрева; отсутствие утечек за часы не доказано. Нужен повтор на 30–60 минут; новые объекты сами могут повышать RAM/VRAM.

## Установка и откат

Закройте игры. Запустите AKU9992-Native12-Fix4-Patch.exe и выберите общую папку с CaCG и CaCGZH. Альтернатива: распаковать AKU9992-Native12-Fix4-Update.zip с заменой файлов. Streamline, VC runtime и игровые архивы должны быть установлены предыдущим Native12 выпуском; патч их не заменяет.

Запускайте generals.exe. FPS: AKU9992-Settings.cmd. Сохранения, Options.ini и выбранные настройки FPS патч не заменяет. Перед установкой можно отдельно скопировать generals.exe, Client/generals-client.exe и Client/generals-native12.dll.

Откат: закрыть игры и распаковать сохранённый AKU9992-Native12-Fix3-Update.zip. Для удаления новых настроек удалить только Client/AKU9992-settings.ini и AKU9992-Settings.cmd. Формат сохранений целенаправленно не менялся; после отката используйте сохранения соответствующего выпуска.

## Сборка и повторение тестов

Требуются Windows, MSVC x64, CMake/Ninja, закреплённые исходники/зависимости, официальный Streamline 2.14.1 и игровые ресурсы. Из корня проекта:

~~~powershell
./tools/Build-X64Game.ps1 -Native12 -Edition Generals
./tools/Build-X64Game.ps1 -Native12 -Edition ZeroHour
./tools/Build-NativeRenderer12.ps1 -W3D -Neural -Test
./tools/Test-NativeFrameTiming.ps1
./tools/Test-ObjectPoolX64.ps1
./tools/Test-X64Audio.ps1
./tools/Test-PerformanceScenarios.ps1 -OutputRoot .build/performance/repeat
./tools/Test-PerformanceScenarios.ps1 -Scenario Movement -FpsMode Custom -CustomFps 15 -Seconds 30 -OutputRoot .build/performance/repeat-15
./tools/Test-PerformanceScenarios.ps1 -Scenario MultiAI -Map 'maps\Twilight Flame\Twilight Flame.map' -FpsMode Standard -Seconds 300 -OutputRoot .build/performance/repeat-long
./tools/Write-PerformanceReport.ps1
./tools/Build-AKUClientPatch.ps1
./tools/Test-NativeClientRelease.ps1 -GameRoot .build/native-client-release/install-check-fix2
~~~

Build-X64Game.ps1 использует isolated pinned source и сохраняет остальные изменения проекта. README, manifest и PE resources проверяются перед выпуском; авторство — AKU9992. Измерения, SHA256 и фактически выполненные проверки находятся в verification.json рядом с патчем.
