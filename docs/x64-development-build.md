# Экспериментальная сборка Zero Hour x64

6 октября 2026: полная игровая сборка скомпилирована и скомпонована MSVC
для AMD64. Она использует зафиксированный community-код
TheSuperHackers/GeneralsGameCode `b805c12ee1aedc0a4b241006803b8e04bbf288a6`
и воспроизводимые патчи из `tools`, а не только переключение архитектуры
у оригинального retail EXE. Заимствованный код и лицензии сохраняются.

Сборка изолирована от Win32 в `.build/community-reference-x64`,
`.build/game-x64` и `.build/d3d12-bridge-x64`. Для первоначального заполнения
зафиксированных исходников и зависимостей используется
`Build-CommunityBaseline.ps1 -ConfigureOnly`; он требует доступа к сети.

```powershell
.\tools\Build-D3D12Bridge.ps1 -Architecture x64
.\tools\Test-D3D12Bridge.ps1 -Architecture x64
.\tools\Build-X64Game.ps1
.\tools\Test-D3DX8Compatibility.ps1
.\tools\Test-X64GameStartup.ps1
.\tools\Install-X64TestBuild.ps1
.\tools\Test-X64GameStartup.ps1 -Installed -Seconds 30
```

## Звук x64

В этой ревизии звук восстановлен через `audio/X64AudioBackend.h`.
Оригинальная mss32.dll не загружается в AMD64-процесс; загрузчик раньше
возвращал false, и MilesAudioManager отключал все категории аудио.
Apply-X64AudioPatch подключает нативный XAudio2 backend к существующему
API менеджера. Игровые события, приоритеты, громкость и расстояние до
слушателя продолжают рассчитываться движком. Backend поддерживает
PCM WAV, IMA ADPCM, MP3 через Media Foundation, стереопанораму, позиционные
источники, музыку, паузу, повтор и завершение звука.

EOS callback только ставит атомарный флаг: обработка выполняется при
MilesAudioManager::update в игровом потоке. Так обработчик может безопасно
заменить source voice или начать следующий участок звука; DestroyVoice
не вызывается внутри потока XAudio2. Дескрипторы завершения звуков передаются
как std::uintptr_t во всём пути до поиска PlayingAudio, без усечения указателя.

```powershell
.\tools\Test-X64Audio.ps1
.\tools\Test-X64GameStartup.ps1 -ShellMap -Fullscreen -Graceful -Seconds 15 -NeuralMode Off -RequireAudio
.\tools\Test-X64GameStartup.ps1 -ShellMap -Fullscreen -Graceful -Seconds 15 -NeuralMode DLAA -RequireAudio
.\tools\Test-X64GameStartup.ps1 -ShellMap -Fullscreen -Graceful -Seconds 15 -NeuralMode DLSSQuality -RequireAudio
```

Native-тест проверяет ненулевой peak аудиосессии своего процесса, паузу,
возобновление, однократный EOS, декодирование игровой музыки и очистку.
Также проверены TDrYes00.wav и AH64.wav из установленной игры.
-RequireAudio проверяет peak **конкретного PID игры**, без записи звуковых
данных или проверки звука посторонних приложений. Установка требует
положительной проверки во всех трёх режимах и штатного выхода.
Лог backend: GeneralsAudio.log в рабочей папке игры. Результаты измерений:
.build/audio-session-{Off,DLAA,DLSSQuality}.log.

Старые Miles DSP-фильтры и DirectSound/Bink API не эмулируются; игровое
аудио использует XAudio2, а порт видео остаётся отдельной задачей.

Исправлены x86 inline assembly и CONTEXT в обработке исключений, размер
системных дескрипторов, указатели в сообщениях окон, хеширование окон,
адреса строк IME и арифметика адресов при загрузке моделей. Старые x86
DirectX import-библиотеки исключены из линковки; используются системные
x64 DirectInput и собственный слой D3DX8 поверх системного D3DX9 x64.
Мост хранит COM-указатели в таблице: публичные DWORD-дескрипторы старого
D3D8 API остаются 32-битными без записи 8 байт в 4-байтовые выходные поля.

При изменении заголовков Build-X64Game автоматически выполняет чистую
пересборку: локализованный `/showIncludes` текущего MSVC некорректно
распознаётся Ninja. Сканирование C++ modules отключено: проект их не использует.

Проверки GPU прошли для state blocks, vertex/pixel shader handles, чтения
отрисованного пикселя и смены разрешения 3440×1440 → 3840×2160.
Отдельно проверены D3DX-матрицы, сборка шейдера и создание/фильтрация
текстуры с проверкой пикселя самого маленького mip-уровня.

Игровой старт с установленными данными прошёл: настоящий ID3D12Device,
первый Draw и Present зафиксированы в `GeneralsD3D12.log`.
Запуск из build-каталога требует `-useCwd`: без него программа ищет
игровые данные рядом с EXE и останавливается при загрузке GlobalData.
Результаты каждого стартового теста: `.build/x64-game-startup.json`.
Проверка старта не подтверждает изображение меню, длительную схватку
или совместимость всех сохранений.

В установленной игре создана отдельная папка `GeneralsGPT-x64` и файл
`Test-X64.cmd` в корне Zero Hour. Это сохраняет существующие Win32-мост,
FPS-тест и оригинальные исполняемые файлы. Мост всё ещё переводит
D3D8 → D3D9On12 → D3D12; полный нативный порт W3D не выполнен.

В меню используются отдельные пункты **DLSS Quality** и **DLAA** в списке
сглаживания; дополнительные кнопки удалены по запросу пользователя.
7 октября подключён настоящий игровой проход DLSS Quality/DLAA. Пункты доступны
при успешной проверке NVIDIA, выбор применяется и сохраняется. Данные движения
непрозрачных mesh включают трансформации и CPU-анимацию; HUD рисуется после
обработки. Подробности, проверки и ограничения: [neural-renderer.md](neural-renderer.md).

## Исправление розовых текстур

После пользовательской проверки обнаружена ошибка дискового формата DDS:
`LegacyDDSURFACEDESC2::Surface` было `void*`. В AMD64 размер всей структуры
увеличился с 124 до 136 байт, сдвинув PixelFormat и Caps. Загрузчик сравнивал
прочитанное число байтов со значением Size=124 и отвергал оригинальные DDS;
движок подставлял розовую missing-texture заглушку. Зарезервированное поле
файла заменено на uint32_t. Размер 124 и смещения PixelFormat=72, Caps=104
зафиксированы static_assert. Исправление добавлено в исходники Generals/Zero
Hour и воспроизводимый x64-патч. Также удалены два усечения pBits до unsigned
int при чтении альфа-канала в SurfaceClass.

`Get-DdsTextureSamples.ps1` читает образцы из BIG-архивов в игнорируемый
build-каталог, не изменяя игру. `Test-D3DX8Compatibility.ps1 -DdsSamples`
проверяет заголовок из настоящего ddsfile.h и загрузку/чтение пикселей
оригинальных DXT1/DXT5 на GPU. Три образца прошли проверку.
Старт игры с `Test-X64GameStartup.ps1 -ShellMap -Seconds 30` также прошёл:
Draw/Present и 32 записи полного чтения DDS-полезной нагрузки подтверждены
журналом `GeneralsDDSLoad.log`. Исправленный EXE установлен отдельным
`Test-X64.cmd`. Внешний вид карты и техники после исправления должен
подтвердить пользователь; автоматическая проверка не сравнивает изображение.

## Подключение базовых текстур Generals

Следующая пользовательская проверка показала, что исправление DDS восстановило
воду и деревья, но остальные поверхности остались розовыми. Диагностика нашла
73 ошибки отсутствующих текстур на фоновой карте. x64 обращался к 64-битному
разделу реестра EA, в котором отсутствовал Generals InstallPath. Базовые архивы
из соседней установки Generals не подключались; оставались только Zero Hour BIG.

`Apply-LegacyRegistryViewPatch.ps1` задаёт KEY_WOW64_32KEY для чтения/записи
старых EA-ключей в x64, сохраняя остальные запросы реестра. Изменение не
редактирует реестр и применяется также к исходникам обеих игр в репозитории.
После исправления 30-секундная проба с фоновой картой прошла с Draw/Present,
а количество ошибок отсутствующих текстур сократилось с 73 до одной.

`Test-TextureArchiveCoverage.ps1` проверил 7111 DDS и 797 TGA из установленных
архивов обеих игр: ошибок заголовков нет. Ошибок загрузки существующих в
архивах текстур в стартовой пробе нет. Единственное оставшееся имя
`trstrtholecvr.tga` не имеет ни TGA-, ни DDS-файла в этих архивах; это отсутствие
исходного ресурса. Проверка заголовков не является GPU-тестом каждого файла
или визуальной проверкой каждой карты. Исправленный EXE установлен через
прежний `Test-X64.cmd`; предыдущие тестовые файлы сохранены в резервных копиях.
